# Cross-solver flat-plate replication (OpenFOAM SA-AI) — figure-script bug + findings
*2026-07-26. Source: independent shallow OpenFOAM port of the sphere-kernel
model (`sa-ai/openfoam/`, model `SpalartAllmarasAI`: cell-centered,
pressure-based incompressible simpleFoam/SIMPLEC, plain `fvc::laplacian(U)·û`
for u″, no fSlow) run on the paper's flat-plate grid spec (Sec. IV: 320×80,
dx0=8e-4, dz0=7e-6, r=1.12, unit Re 1e6), all five Tu cases, machine-converged
(worst case: Cd limit cycle ±0.08%). Diagnostic scripts + figures:
`sa-ai/openfoam/scripts/regen_flatplate_compare.py`,
`flatplate_fig_{openfoam,flow360}.pdf` (paper-identical layout, both solvers).
Full log also in RESPONSES.md (2026-07-26 entry).*

## Major

1. **10× χ-normalization bug in `paper/regen_flatplate_flow360.py` (line ~19,
   `NU = 1.0e-6`).** Flow360's `nuHat` output is in c∞·L units, so
   χ = nuHat/ν requires ν = M/Re = **1e-7** for the flat plate (the same
   ONBOARDING §5 convention the Eppler scripts use, NU = 0.1/Re; the script's
   comment "nu = 1/Re" is the error). Verified directly on the raw output:
   freestream nuHat in `flow360_fr/flatplate_sphere_Tu0040/volume.pvtu` is
   1.92e-11 → χ∞ = 1.92e-4 with 1e-7, right at the intended Mack seed
   2.28e-4; with the script's 1e-6 it reads 1.9e-5, 12× below the seed the
   case was built with. Consequences for the paper:
   - Every χ quantity in `flat_plate_batch_flow360` (χ(x) curves, contour
     labels in the log₁₀χ panels, the χ=1 and χ=c_v1 reference-line
     positions relative to the curves) is displayed a decade low; the
     figure's apparent "χ=1 crossing" is the actual χ=10 crossing, i.e.
     systematically LATE. The Cf and Re_θ panels are unaffected (velocity
     conversion /M is correct).
   - Any text numbers derived from this script's `ONSET_DIAG` path
     (`onset_vs_ags()`) carry the same lateness and should be re-derived
     after the one-line fix.
   - How it was caught: the OpenFOAM max-χ(x) sat a CONSTANT ~11.7× above
     the Flow360 curves at all stations and all five Tu — a pure offset
     with identical growth slope, i.e. a units error, not physics.

2. **With the normalization corrected, the true χ=1 crossings vs AGS steepen
   with Tu — in both solvers.** Corrected Blasius-converted onsets
   (Re_θ = 0.664√Re_x at the χ=1 crossing):

   | Tu% | Flow360 vs AGS | OpenFOAM vs AGS |
   |-----|----------------|-----------------|
   | 0.04 | +5.4% | +1.8% |
   | 0.08 | −4.1% | −8.5% |
   | 0.16 | −12.8% | −17.2% |
   | 0.30 | −18.7% | −23.1% |
   | 0.60 | −22.3% | −26.5% |

   The flat-in-Tu deviation the current (buggy) figure suggests is partly an
   artifact: reading the crossing a decade up the χ(x) curve compresses the
   Tu spread because the post-crossing slopes differ. If the flat-plate
   section quotes agreement-with-AGS trends, re-check them against the
   corrected crossings. (The Cf-min onset metric, which the S–S band
   comparison uses, is unaffected.)

3. **Flow360's converged freestream seed runs ~16% below intended**
   (χ∞ = 1.92e-4 measured vs 2.28e-4 built, Tu=0.04; same relative shortfall
   at Tu=0.16). This is the fSlow freestream-BC compensation not being exact
   (ONBOARDING §7 caveat). ln(2.28/1.92) ≈ 0.17 N-units ≈ +2% in crossing
   Re_θ — small but systematic, and it is a *solver-artifact* seed error the
   paper's Mack-map narrative silently absorbs. Worth a sentence if the seed
   values are quoted as exact, or a check on whether the Eppler/NLF runs
   (also fSlow-staged) carry the same shortfall.

## Supporting result (positive — usable in the paper if desired)

4. **Cross-solver robustness of the model formulation.** After the
   normalization fix, an independent implementation in a maximally different
   solver (cell- vs node-centered, pressure- vs density-based, incompressible
   vs M=0.1, segregated SIMPLE vs coupled implicit, plain compact Laplacian
   vs ring-averaged pre-pass, no fSlow) reproduces the flat-plate transition
   with NO trend across the 15× seed range:
   - χ=1 crossing Re_x: −7 to −10.5% (Re_θ: −3.5 to −5%), uniform in Tu;
     ~2% of it explained by item 3 (OpenFOAM holds the seed exactly).
   - Cf-min onset Re_x: −4 to −10%; Tu=0.04 falls inside the S–S band.
   - Same limit-cycle phenomenology at the most marginal case (Tu=0.04,
     ±0.08% Cd), without any fSlow machinery — supporting the paper's
     framing of the cycle as a model property, not a solver artifact.
   If a "discretization/solver independence" remark would strengthen the
   flat-plate section, these numbers are available; reproduction is
   `sa-ai/openfoam/README.md` (one library + five blockMesh cases, ~1 h/case
   serial).
