## New major comments

1. **The "within 5% in Re_θ" P1-18c sentence is contradicted by Table F1**
   (sa-ai.tex ~1395–1399: "reproduces the onset crossings quoted below within
   5% in Re_θ uniformly across the sweep"). From the committed table: χ=1
   differences are 4.4/5.3/5.6/6.3/7.1% (Tu=0.04→0.6) and χ=c_v1 differences
   4.1/6.1/5.0/9.3/14.0%. Nothing in the table is within 5% "uniformly"; the
   c_v1 crossing at Tu=0.6 is off by 14%. The sentence predates the summary
   export (bd8b861) and now sits two pages from the table that falsifies it.
   Reword to what the data supports (e.g. "within 7% at the χ=1 crossing,
   the OpenFOAM front consistently slightly early") and cite Table F1. The
   flat-plate caption's separate "brackets AGS within 10%" claim survives
   (Flow360 c_v1 vs AGS: max 9.9% at Tu=0.3) — but only just; keep an eye on it.
2. **OpenFOAM provenance is almost entirely uncommitted** (repro-code
   criticality). In git: only `openfoam/scripts/export_flatplate_summary.py`,
   the summary JSON, and the Appendix G PDF. Not in git: the
   `SpalartAllmarasAI` model source (`openfoam/src/`), the case builders and
   run scripts, `openfoam/README.md` (which the committed JSON's `source`
   string explicitly points to), the `openfoam-unstructured-failures.md`
   evidence behind the mesh-family sentence, and — critically —
   `regen_flatplate_compare.py`, which both **generates the Appendix G figure**
   (byte-identical copy) and is **imported by the committed exporter**, so even
   the one committed script fails on a clean checkout. Appendix G's figure
   currently has no committed generator at all. The code tree is small and
   self-contained; commit it (src + scripts + README + failures doc).
3. **`emit_appendix_tables.py` silently degrades and ignores a committed data
   source.** The Eppler extension rows (−2, 1, 3, 4, 6, 8.5) come from
   `tail_forces()` over uncommitted `flow360_fv1/` case CSVs, with
   `FileNotFoundError → ('--','--')` — on a clean checkout F3 regenerates with
   holes and no error (exactly the silent-skip pattern pass 38 queued for
   elimination, and the opposite of a6cbd01's asserted overlay). Meanwhile
   `flow360_fv1/sphere_campaign_eppler_ext_results.json` **is committed** and
   carries all 12 extension cases — and disagrees with the table in the last
   digit (str am2: JSON 0.1752/0.01089 vs table 0.1750/0.01088), so the paper
   currently tabulates values that differ from the committed campaign record.
   Load the ext JSON the way `nlf()` loads the neg JSON and hard-fail on
   missing keys. Same pattern: `nlf()` drops a whole α/level row silently when
   both families are absent (`found=False`), so a renamed campaign key would
   just shrink the table.
