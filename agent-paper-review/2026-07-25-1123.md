## New major comments

1. **fig:eppbubble's legend advertises a series that is not in the
   figure.** `regen_epp_bubble_figure.py` draws the data branch
   conditionally (`if pts:`) but appends the `Line2D` legend handle
   "XFOIL ($e^9$, $\alpha\ge6.5^\circ$)" unconditionally — and the
   committed `mfoil_eppler_bubble_sweep.json` `xfoil` block is six
   all-null `conv:false` records (the XFOIL 6.99 run SIGFPE'd, per
   the commit message). The shipped figure therefore shows a dash-dot
   legend entry with no curve on either panel; the caption never
   mentions it. A referee will hunt for the missing curve. Fix:
   gate the legend handle on the same `if pts:` (or land the branch
   via the continuation ramp / FlexFoil). Compounding it, the
   pass-23 response file committed *in this same commit* states
   "fig:eppbubble gained an XFOIL e^9 branch for α≥6.5" — false as of
   e30e71d; the commit message is the accurate record. Restoring the
   old table footnote's XFOIL 0.40c at α=7° (lost in the promotion)
   should ride along with whichever fix is chosen.

2. **The α=−8° points added to fig:nlfaft disagree grossly with every
   reference on the figure, unacknowledged — and the lower-surface
   point is silently clipped out of frame.** At cl≈−0.47 the SA-AI
   upper-surface front plots at 0.14c (str) / 0.22c (cav) where the
   LTPT experiment reads 0.50–0.55c and the AFT curves ~0.55c — a
   0.3–0.4c miss displayed in plain sight with no caption or body
   comment. On the lower panel the story is worse: the model holds
   the lower surface laminar to 0.89c (verified independently from
   the surface VTU: the −Cp=4.7 leading-edge suction spike fails to
   trip it) where XFOIL/AFT trip at ~0.01c — and 0.89 lies beyond the
   panel's `xlim(0, 0.75)`, so the point is invisible. The result:
   the figure quietly displays one large disagreement and quietly
   hides its twin. The RESPONSES entry quotes only the benign am4
   fronts. Whatever the physics (a real strong-negative-incidence
   failure mode of the untuned seed? an LE-resolution artifact?),
   the paper cannot carry these markers without a sentence — either
   diagnose/caveat the −8° fronts in the caption (the forces are
   fine; the fronts are not), extend the xlim so the reader sees the
   lower point, or drop the −8° transition markers and keep the pair
   polar-only. Selective display of the flattering half is exactly
   what this paper's fair-comparison posture has so far avoided.

   trim the docstring.

4. **`run_mfoil_bubble_sweep.py` main path silently destroys the

   without warning (this pass it's all-null anyway; once the branch
   lands it becomes a live provenance hazard). Merge-then-write like
   the xfoil path does. Same one-cell-late note as the deletion
   audit: `tr = x[neg[-1]+1]` is an uninterpolated upper bound
   (~0.01c late at α=0° vs the old table's interpolated value);
   interpolating the crossing would make mfoil's dotted curve
   consistent with the SA-AI extraction, which does interpolate.

5. **`extend_invk_cases.py` (invariant-kernel restart harness) landed
   in `paper/repro/cfd/` inside the eppbubble commit.** The paper
   never mentions the invariant kernel (checked: the only "invariant"
   hits are Galilean/rotation-invariance statements — correct, since
   the matched-protocol verdict is FAILS/not-cleared per RESPONSES

   extension memo's tooling) at the next tidy.
