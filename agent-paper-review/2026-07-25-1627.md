## Equivalence audit

**1. The identity eq:gram ≡ implemented magnitude kernel: TRUE
(for |u| > 0), verified symbol-by-symbol and numerically.**

Implemented triple (`SAAiTransition.h` ll. 144–151 + call site
`SpalartAllmaras.h` ll. 309–331): X = velMag = |u|; Y = vortMag·d
(full vorticity magnitude); Z = −½d²·dwdn with dwdn = −uppAi and
uppAi = (one-ring compact ∇²u)·û, i.e. Z = +½d²(∇²u)·û. Multiply by
|u| > 0:

- |u|·X = |u|² = ⟨u,u⟩ ✓
- |u|·Y = |u|·d·|ω| = √(⟨u,u⟩⟨d,d⟩⟨ω,ω⟩) ✓ (with 𝐝 = d∇d and
  |∇d| = 1, so ⟨d,d⟩ = d²; see minor 4)
- |u|·Z = ½d²(∇²u)·u = ⟨ℓ,u⟩ ✓ (ℓ = ½⟨d,d⟩∇²u, and the tex's Y
  convention keeps the FULL ⟨ω,ω⟩, matching the code's vortMag — the
  RESPONSES ~01:00 "Y-convention pinned" decision is faithfully
  rendered)

Ŝ = Y/√(X²+Y²) and g = (Y−X−Z)/R are homogeneous of degree zero, so
P = Ŝg computed from either triple is identical. Numerical check
(10⁵ random 3D states, |∇d|=1): max |P_implemented − P_gram| =
8.9×10⁻¹⁶. The parallel-layer reduction sentence ("reduces to the
magnitude triple (|u|, d|u′|, ½d²u″sign(u)) times the positive factor
|u|") checks exactly. The onset gate is untouched (Re_Ω = d²|ω|/ν in
both). **Verdict: the presented equations are what produced every
number in the paper.**

Two boundary caveats, neither canon-affecting: (a) the identity needs
|u| > 0 — at an exact-stagnation node the Gram entries all vanish
(the zero vector is not a projective representative) and a literal
eq:gram evaluation returns P = 0 where the implemented ratio form has
the finite limit Ŝ = 1, g = (Y−Z)/√(Y²+Z²) (my probe: P = 1.0 vs
0.0). Measure-zero, guard-scale, no practical consequence for the
ratio-form solver — but it matters for anyone reimplementing from
eq:gram (major 3). (b) "any common positive factor drops out" is
correct as stated; P is in fact invariant under any nonzero common
factor (Ŝ and g are each odd), which is what makes the mixed-sign
discussion of the following paragraph work.

**2. AI_INVARIANT_KERNEL=2 is NOT the presented kernel, and the tex
does not silently describe it.** Eq. (eq:gram) pairs the triple
against **u** (the magnitude class); the =2 kernel pairs against
**m = ω×𝐝** (the signed class):
P₂ = (⟨m,m⟩−⟨m,u⟩−⟨m,ℓ⟩)/√((⟨m,m⟩+⟨u,u⟩)(⟨m,m⟩+⟨u,u⟩+⟨ℓ,ℓ⟩))
(`__aiRatePair`, `SAAiTransition.h` ll. 197–233). The tex prints the
signed pairing ⟨ω×𝐝,u⟩ with its rejection verdict — accurate against
the record (four signed variants: s_hat/=1 +12.4/+22.3/+10.8 counts;
projected Gram +14.2/+28.5/+23.5; unprojected =2 +13.7/+23.6/+23.8;
=3 within 0.2 ct of =2; root cause = signedness rectifying
ω-direction noise in weak shear, magnitude form immune by
construction).

Code-path audit: env AI_INVARIANT_KERNEL → ai_invariantKernel
(`SATurbulenceSolver.cpp` ll. 136–137, echoed in the resolved-
constants log l. 172), compiled default 0.0 (`ModelConstants.h`

## New major comments

1. **"rescaling Eq.~(eq:indicators) by |u| gives the implemented
   representative" (l. 1348) is false in the mixed-sign layer — the
   same regime the adjacent paragraph treats with care.** Eq.
   (eq:indicators) is the *signed* triple (u, du′, ½d²u″)/R;
   rescaling it by |u| (or any common factor) preserves its
   projective class, but eq:gram's middle entry is the *magnitude*
   |u|d|ω| — the envelope of the rescaled signed entry |u|·du′, not
   the entry itself. Where sign(u′) ≠ sign(u) the two triples are
   different RP² points and give different P (numeric
   counterexample: signed-rescale P = +0.402, eq:gram/implemented
   P = −0.202 — precisely the deviation ll. 1383–1407 then localize
   and bound). As printed, l. 1348 asserts an equivalence the
   paper's own next paragraph refutes. One-clause fix: "rescaling
   the solver's magnitude realization of Eq.~(eq:indicators) by
   |u|" (or derive eq:gram from the magnitude triple stated in the
   reduction sentence, and let the existing realization paragraph —
   which is exactly right and untouched — carry the signed-class
   relation).

2. **"whose Cauchy--Schwarz \emph{envelope} is exactly
   Eq.~(eq:gram)'s middle entry" (ll. 1369–1371) is exact only in
   two dimensions.** The C-S envelope of ⟨ω×𝐝,u⟩ is
   √(⟨u,u⟩⟨m,m⟩) = √(⟨u,u⟩(⟨d,d⟩⟨ω,ω⟩ − ⟨ω,d⟩²)) — by the Lagrange
   identity this is ≤ the middle entry, with equality iff ω ⊥ 𝐝
   (all 2D flows; generic 3D layers have ⟨ω,d⟩ ≠ 0 — my probe:
   envelope 0.113 vs middle entry 0.723 for a deliberately tilted
   ω). The RESPONSES ~00:15 derivation keeps this distinction
   explicitly (its point 3: the tangential and full-Y choices differ
   by the wall-normal-vorticity pairing, "identical in 2D, i.e., the
   whole calibration domain"); the tex collapsed it into an
   unconditional "exactly". The rejection *logic* survives (an
   envelope never flips sign with ω-noise either way), so the fix is
   one clause: "... is exactly Eq.~(eq:gram)'s middle entry in
   two-dimensional flow (and its lower bound in three, by the
   Lagrange identity ⟨m,m⟩ = ⟨d,d⟩⟨ω,ω⟩ − ⟨ω,d⟩²)".

3. **"the implemented representative ... no unit vector is ever
   constructed, no division by a vanishing magnitude can occur"
   (ll. 1349, 1359–1360) claims for the implementation properties
   only the representative has.** The code constructs û through a
   1e-30-guarded division (`SpalartAllmaras.h` ll. 325–330,
   invVelAi) and evaluates the ratio triple (|u|, ωd, ½d²(∇²u)·û);
   it never computes a Gram pairing. And at |u| = 0 the two are not
   interchangeable: a literal eq:gram implementation returns P = 0
   at stagnation nodes where the ratio form has the finite
   magnitude-kernel limit (P up to 1). This is the pass-5 mismatch
   class at the wording level — harmless to the numbers, but a
   reader porting the model from eq:gram will build something that
   (a) is not bit-comparable to what produced the paper's results
   and (b) differs at stagnation. Either reword ("an equivalent,
   division-free representative of the implemented triple; the
   solver evaluates the ratio form, the two coinciding wherever
   u ≠ 0") or actually move the solver to the Gram arithmetic and
   re-verify — but don't claim the second while shipping the first.

4. **The adoption never reached Appendix E — the "complete model in
   one place" now states a third, inequivalent curvature form.**
   Appendix E's assembled model (ll. ~3507–3524) still defines
   Z = ½d²·n̂·∇ω — the nested vorticity-magnitude-gradient form the
   implementation comment (`SpalartAllmaras.h` ll. 309–316)
   explicitly *dropped* as noisy — with the implemented (∇²u)·û
   relegated to a following "the implementation evaluates ..."
   sentence, and no mention of the Gram presentation at all.
   n̂·∇|ω| and (∇²u)·û are different fields: on a parallel layer
   they differ by sign(uu′) (mixed-sign band again), and in 3D they
   are not related pointwise. Pre-existing (the App-E line predates
   b8cac0e), but a commit titled "Adopt the Gram-form presentation"
   that leaves the appendix on a form *neither* Sec. III nor the
   code uses turns a latent inconsistency into an active one: Sec.
   III says ⟨ℓ,u⟩, Appendix E says n̂·∇ω, the solver computes
   (∇²u)·û. Make Appendix E's primary statement the same as Sec.
   III's (Gram or ratio, either is fine — they're now proven equal),
   and keep n̂·∇ω only as the parallel-layer reading if at all.
